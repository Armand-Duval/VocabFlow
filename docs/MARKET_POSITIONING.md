> **更新：** 2026-07-29

## 1. 调研摘要

### 1.1 调研目的

厘清 **Recall（稍后读）**、**Knowt（AI 闪卡平台）** 的产品调性与能力边界，明确 **KnoWell** 在「收藏 → 学习 → 记住」链路中的位置，避免与二者同构竞争。

### 1.2 核心结论（Executive Summary）

| 产品 | 一句话定位 | 用户心智 | 核心动词 |
|------|------------|----------|----------|
| **Recall** | 为认真读者做的稍后读工具 | 「先收进来，以后再读」 | 收藏 · 阅读 · 重温 |
| **Knowt** | AI 驱动的学生闪卡与学习平台 | 「把材料变成卡，在平台里学」 | 生成 · 练习 · 掌握 |
| **KnoWell** | 通用文本精读闪卡：摘录 → AI 制卡 → SRS | 「摘录所读，记住所得」 | 摘录 · 提炼 · 复习 |

**战略位势：**

```
Recall ──(收藏/阅读)──▶ 用户大脑 ──(遗忘)──▶ ？
                              ▲
Knowt ──(AI 制卡/平台)────────┤
                              │
KnoWell ──(语境卡 + SRS)──────┘   ← 占「记住」这一环
```

KnoWell **不应** 复制 Recall 的阅读器，也不应 **正面硬刚** Knowt 的 AI 平台与考试资源库；应聚焦 **「Recall 之后、Knowt 之外」的记住层**。

### 1.3 调研方法

- App Store 产品说明与用户评价（Recall，2026-07）
- Knowt 实机体验与界面走查（2026-07）
- 与 KnoWell 现有能力对照（Share Extension、Anki 导入、SRS、Calm Study UI）

## 2. Recall — 产品剖析

### 2.1 基本信息

| 项 | 内容 |
|----|------|
| **App Store 名** | recall（小写） |
| **品类** | 效率 / 稍后读 / 阅读器 |
| **开发商** | 上海麟杰智勇（classmelon.com） |
| **平台** | iOS 原生（iPhone / iPad / Mac） |
| **评分** | App Store 约 5.0（样本量较小） |

### 2.2 产品调性（Brand Tone）

| 维度 | 描述 |
|------|------|
| **情绪** | 安静、克制、隐私优先、无打扰 |
| **气质** | 原生 iOS、阅读器、个人书库 |
| **用户关系** | 「你的文章只属于你」— 工具 servant，非导师 |
| **压力感** | 低：无 streak、无排行、无社交 |
| **视觉** | 白底 + Teal 渐变、小写 recall、卡片列表 |

**官方 Slogan（提炼）：**

> 好内容值得收藏，好灵感值得重温。

**命名逻辑：** Recall = 回顾、重温；强调 **「再次接触内容」**，而非 **「检验记忆」**。

### 2.3 价值主张

**解决的问题：**

微信文章、博客、新闻 **「收藏了却从不读」** — 内容散落于收藏夹与标签页。

**核心承诺：**

1. **看到就存** — 系统分享菜单一键保存  
2. **读得干净** — 去广告、净文、离线、网页快照  
3. **理得清楚** — 文件夹、全文搜索、归档、未读状态  
4. **数据归你** — 无注册、iCloud 同步、无广告、无推荐算法  

### 2.4 功能结构

```
输入层          处理层           消费层           管理层
─────────────────────────────────────────────────────
Share 分享      净文提取         阅读器           文件夹
URL 导入        网页快照         高亮 + 笔记      全文搜索
RSS 订阅        离线缓存         列表 / 瀑布流    归档 / 未读
                主题字体                          Widget
```

### 2.5 商业模式

| 版本 | 能力 |
|------|------|
| **免费** | 最多 200 篇文章、RSS、搜索、文件夹、iCloud、深色模式 |
| **Pro** | 无限收藏、无限高亮笔记、导出 MD/PDF、阅读统计、无限 RSS |
| **付费形态** | **断制买断或订阅二选一**（强调老用户不涨价） |

### 2.6 目标用户

- 重度信息消费者、独立开发者、爱读长文的人  
- 需要 **跨 App 收藏**（微信、Twitter、小红书等）  
- 重视 **隐私与无账号**  
- **不** 以「背单词 / 考试刷题」为主诉求  

### 2.7 能力边界（KnoWell 需认清）

| ✅ Recall 强 | ❌ Recall 不做 |
|-------------|---------------|
| 文章收藏与阅读 | SRS 间隔复习 |
| 高亮与笔记 | 闪卡 / 测验 |
| 稍后读工作流 | Anki / 词汇 deck |
| 阅读统计 | AI 制卡平台 |
| | 考试资源库 |

**关键缺口：** 用户「重温」了内容，但 **没有系统帮其转化为长期记忆**。

## 3. Knowt — 产品剖析

### 3.1 基本信息

| 项 | 内容 |
|----|------|
| **品类** | 教育 / 闪卡 / AI 学习 |
| **市场** |  primarily 北美学生 |
| **平台** | iOS / Web |
| **定位** | AI note-to-flashcard + 学习平台 |

### 3.2 产品调性（Brand Tone）

| 维度 | 描述 |
|------|------|
| **情绪** | 简洁但 **偏活跃** — 有 gamification |
| **气质** | 现代 SaaS、AI 产品、学生平台 |
| **用户关系** | AI 助手（**kai**）+ 学习教练 |
| **压力感** | 中：连胜 🔥、等级 LV、金币 |
| **视觉** | 白底圆角、彩色功能图标、九宫格入口 |

**命名逻辑：** Know + t — 与 **Knowledge / 学会** 关联；偏 **掌握（Master terms）**。

### 3.3 价值主张

**解决的问题：**

讲义、PDF、录音 **→ 如何快速变成可练习的学习材料**。

**核心承诺：**

1. **多源输入** — 上传文件、拍照、录音、手动、Quizlet 导入  
2. **AI 生成** — kai 自动生成 Term/Definition 闪卡  
3. **平台资源** — AP/SAT/ACT、学科 topic、用户共建内容  
4. **多种学法** — 闪卡、SRS、games、podcast、practice test  
5. **协作** — Class、社区向内容  

### 3.4 功能结构

```
输入层              AI 层               输出层              平台层
──────────────────────────────────────────────────────────────────
Upload / Photo      kai 理解            Flashcards          Resources
Live Record         自动抽 term         Notes               Classes
Quizlet import      聊天制卡            Practice tests      Explore
Manual term/def                         Podcast             Gamification
```

### 3.5 商业模式（公开信息推断）

- Freemium + AI 额度限制（与多数 EdTech 一致）  
- 平台内容与服务增加粘性  
- 面向 **学生考试场景** 转化 Pro  

### 3.6 目标用户

- 北美中学生 / 大学生  
- AP、SAT、课堂笔记 → 考试  
- 习惯 **Quizlet** 生态  
- 需要 **AI 代劳制卡**，而非手动 Anki  

### 3.7 能力边界

| ✅ Knowt 强 | ❌ Knowt 弱 / 不做 |
|------------|-------------------|
| AI 一键制卡 | 语境 / 情景回忆 |
| 考试资源库 | Anki apkg 深度兼容 |
| 多模态输入 | 无 streak 的 calm 复习 |
| 平台与 Class | 中文阅读流 Share 场景 |
| 游戏化练习 | 本地开放工具姿态 |

**卡片模型：** Term ↔ Definition — **孤立词条**，弱「当时在哪个句子、哪篇文章里遇到的」。

## 4. KnoWell — 产品方向（本项目的定位）

> **2026-08-02 定稿：** 路线 = **通用文本精读 + 知识卡片**（非「只做外文」；外文精读可作为冷启动宣传切口）。

### 4.1 一句话定位

从任意文本里摘出句子与知识点，AI 做成卡片，用间隔重复记住。

| 维度 | KnoWell |
|------|---------|
| **赛道** | 介于笔记软件与单词 App 之间：摘录 → 提炼 → 复习 |
| **North Star** | 把读过的、见过的，变成记得住的 |
| **Slogan** | 摘录所读，记住所得 · *Turn reading into memory.* |
| **Daily Tone** | Calm Recall — 随手、安静、情境、继续 |
| **情绪** | 低压力、无 streak / 社交绑架 |
| **气质** | iOS 原生 + 开放工具（非封闭平台） |
| **用户关系** | 复习册 / 记忆助手（非 AI 导师、非阅读器、非社区） |

**命名：** **致知 / KnoWell** — 副标题：文本精读闪卡 · 兼容 Anki。

### 4.2 价值主张

**解决的问题：**

1. 读过的词、句、概念、金句 **会忘**（中外文均可）  
2. 收藏之后 **缺少可复习的卡片闭环**  
3. Anki 用户需要 **更 Calm 的 iOS 体验**  
4. 不想被 **应试词库、连胜、社区、平台题库** 绑架  

**核心承诺：**

1. **复习优先** — 打开即 due，评完即走  
2. **文本/句子为单位** — 语境卡优先于孤立 term  
3. **开放工具** — Anki apkg、JSON、Share 制卡、本地 deck  
4. **Calm Recall** — 无金币排行、无社交发芽广场、无考试资源首页  

### 4.3 功能结构（现状 + 方向）

```
输入层              处理层               记忆层              开放层
──────────────────────────────────────────────────────────────────
Share Extension     OCR / AI 制卡        SRS 复习             Anki apkg 导入
（已有）            （部分已有）          （已有）             JSON 导出（含进度）
剪贴板 / 手动        来源元数据           due / 续上 deck      本地 SwiftData
Anki 导入           （待加强）           语境正面              可选账号同步
```

**验收过滤：** 新功能是否让「摘录 → 提炼 → 复习」更快更稳？否就砍。

### 4.4 目标用户

| 优先级 | 人群 | 痛点 |
|--------|------|------|
| P0 | 深度阅读者（书 / 文 / 论文 / 外刊） | 摘录句子与知识点并记住 |
| P0 | Anki / 闪卡老用户 | 要 iOS 好体验 + 导入导出 |
| P1 | 不喜欢游戏化背单词的人 | 要 calm、工具感 |
| P2 | Recall 用户 | 已收藏很多，想 **记住** 而不仅是 **重读** |

### 4.5 刻意不做（守住定位）

- 文章阅读器 / RSS（Recall 主场）  
- 以应试海量词库为主卖点（墨墨主场；内置词库仅可选补充）  
- AP/SAT 资源库 / Class（Knowt 主场）  
- 连胜、金币、排行榜、社区分享 /「发芽」广场  
- 首页知识图谱大盘、网课、题库

### 5.3 用户旅程对比

**Recall 典型路径：**

```
刷微信 → Share 到 recall → 稍后读 → 高亮 → 归档
                                    ↓

```

```

```

**KnoWell 目标路径：**

```

     或 Anki 导入 ──────────────────────────────────────────────┘
```

| **参考** | 买断 + 订阅 | 订阅为主 | 可考虑 Recall 式买断选项 |

## 6. 差异化机会与风险

### 6.1 KnoWell 的差异化（机会）

| # | 差异点 | 针对竞品缺口 |
|---|--------|--------------|
| 1 | **记住层** | Recall 只到「重温阅读」 |
| 2 | **语境 SRS** | Knowt 默认 term/def |
| 3 | **Calm + 复习优先** | Knowt 首页平台化 |
| 4 | **Anki 开放生态** | 二者均弱 |
| 5 | **Share 阅读流** | 比 Knowt Upload 更贴「随手」 |
| 6 | **中文场景** | Recall 偏读文章；Knowt 偏北美考试 |

### 6.2 风险

| 风险 | 说明 | 应对 |
|------|------|------|
| **Recall 用户重叠** | 都强调 Share、重温 | 明确 **不做阅读器**，做 **制卡 + SRS** |
| **Knowt 用户重叠** | 都是闪卡 | 强调 **语境 / Anki / 无 streak** |
| **名字 Knowt 近似** | KnoWell 拼写 | 副标题 + 行为差异 |
| **Recall 占 Recall 词** | 无法用作 App 名 | 使用 KnoWell |
| **scope 膨胀** | 想做阅读器 + 平台 + 图谱 | 守 DESIGN.md 远景边界 |

## 7. 产品启示与 v1 优先级

### 7.1 向 Recall 学什么

| 启示 | KnoWell 动作 |
|------|--------------|
| 「重温」叙事 | 文案、副标题、复习 CTA |
| Share 为核心入口 | Share Extension 置顶宣传 |
| 来源 / 日期 / 状态 | 卡片与词库行展示元数据 |
| 无账号信任感 | 本地优先，账号可选 |
| 原生 + 简洁 UI | 延续 Calm Study / Teal |

### 7.2 向 Knowt 学什么

| 启示 | KnoWell 动作 |
|------|--------------|
| 制卡入口清晰 | Create Tab 保持短路径 |
| AI 辅助 | 保留生成，但不抢复习首页 |
|  onboarding 简洁 | 首屏聚焦「开始复习」 |

### 7.3 不学什么

- Recall 的阅读器、RSS、200 篇限额逻辑  
- Knowt 的 streak、Resources、Class、Term/Definition 默认形态  

### 7.4 v1 建议优先级

| 优先级 | 项 |
|--------|-----|
| P0 | 复习首页 due + 一键开始 |
| P0 | 卡片 **来源句 / 来源 App** 字段与展示 |
| P0 | Share → 制卡 → 进入 due 闭环 |
| P1 | 词库行：来源 + 日期 + 未掌握数 |
| P1 | 续上上次 deck |
| P2 | iCloud 同步（无账号） |
| P2 | 链接导入 → 制卡（不做完整阅读器） |
